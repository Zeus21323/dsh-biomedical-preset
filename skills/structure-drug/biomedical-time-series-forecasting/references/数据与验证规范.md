# 数据与验证规范

## 输入要求

- 一列严格可排序的时间；
- 一列或多列数值序列；
- 重复时间点的聚合规则；
- 缺失值与检测下限的含义；
- 预测步数及其对应的真实时间跨度；
- 多对象数据必须提供对象标识，不能拼成一条序列。

## 验证设计

1. 使用滚动起点或扩展窗口回测。
2. 评估 MAE、RMSE 或尺度无关误差，并报告预测区间覆盖率。
3. 与最近值、季节性朴素法和领域常用模型比较。
4. 在受试者级别检查泛化，避免同一人的未来数据泄漏。
5. 对干预、设备更换和采样频率变化分层报告。

## TimesFM 2.5 接口边界

- 官方 PyTorch 检查点为 `google/timesfm-2.5-200m-pytorch`。
- 模型需要先使用 `ForecastConfig` 编译，再调用 `forecast`。
- 分位数输出的第一维是批次，第二维是预测步，第三维包含均值和分位数。
- 序列过长会按 `max_context` 截断；内部缺失如何处理必须在报告中记录。
- 对允许负值的生物信号，不应启用只适合非负序列的自动约束。

官方接口说明：<https://github.com/google-research/timesfm/blob/master/timesfm-forecasting/references/api_reference.md>

## 执行依赖

实际推理需要 Python 3.12 以上、`numpy`、`torch` 和与 2.5 API 匹配的 `timesfm`。模型加载可能访问 Hugging Face 并下载大权重，所以脚本默认只做 dry-run，只有显式传入 `--execute` 才进入模型加载。正式运行还需记录模型 ID、解析后的包版本、设备和缓存策略。
