# 分子结构标准化与格式转换

## 制定规则

先说明下游是身份登记、QSAR、相似性、对接还是采购，因为父分子、质子化态和互变异构体的处理并不相同。所有操作从原始结构副本开始，并给每条输入分配稳定记录ID。

## 处理顺序

1. 解析文件并单列失败、空结构和不支持的元素；不能静默丢弃。
2. 按项目规则处理混合物、溶剂和盐，规范键型、芳香性、电荷与同位素；同时保留原始结构到父分子的映射。
3. 明确是否枚举或固定质子化态、互变异构体和未定义立体中心。下游对接可生成多个状态，身份库则通常不能随意扩增。
4. 生成规范SMILES、InChI/InChIKey和所需三维格式，记录软件、版本与规则集。
5. 转换后重新解析并比较原子、键、电荷、立体中心和分子式；SDF到PDB等格式能力较弱时明确可能丢失的化学信息。

## 交付

输出标准化结构、原始—规范映射、规则日志、失败与警告清单以及回读验证。标准化没有唯一答案；关键立体化学、同位素或共价连接不得为追求统一而被抹去。
