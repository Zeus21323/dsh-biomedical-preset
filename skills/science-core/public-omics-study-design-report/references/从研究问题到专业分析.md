# 从零技术表达到专业任务

## 识别方式

同时读取用户目的、已交文件、已完成结果与异常信号。不依赖单个关键词；疾病或基因本身不能决定算法。对“发文章、毕业、做课题”先形成问题、可获取证据和可行范围，少量询问事实而不是让用户选技术。研究建议不自动授权下载全部数据、调用收费服务、训练模型或上传隐私数据。

## 条件分流

| 用户可能说的话或隐含需要 | 必须先发现的证据 | 应用任务与入口 |
| --- | --- | --- |
| “这个基因为什么变高”“这些开放区域有什么用”“审稿人问上游调控” | peaks/染色质数据及匹配注释；没有则先评估数据可得性 | 03 的增强子与靶基因关联：peakScout 位置映射只作基线 |
| “模型特别准是真的吗”“换个病人也差不多”“帮我检查能否写进文章” | 特征、标签、切分、预测；重推理还需模型 | 00 的机器学习训练与评估：标签来源、输入不变性和基线审计 |
| “想找一组一起变化的基因”“RNA和蛋白怎么联系”“模块换队列就没了” | 多样本矩阵、配对/非配对关系和性状 | 11 的 WGCNA共表达网络：分层网络、跨层关联、保留性 |
| “测序公司给了这些文件”“我想把单细胞数据分析完”“已经有矩阵别重新跑” | 实际文件与建库记录，区分 FASTQ、计数、AnnData 和已有结果 | 05 的单细胞分阶段分析工作流或已适配 nf-core 入口；EISCA按阶段检查 |
| “组织里哪些细胞靠在一起”“给了一套Xenium/MERFISH文件” | 成像平台、分子表/图像/坐标或已处理对象 | 06 的空间转录组分析：EISTA只用于支持的平台和阶段 |
| “研究水稻抗逆基因”“这段植物DNA有何区别” | 植物物种、参考与序列窗口，研究任务能由序列模型辅助 | 21 的植物长上下文基因组序列建模；BOTANIC资源不齐先检查，不冒充预测 |
| “不同部位的细胞是不是同一克隆”“单细胞数据还能找突变吗” | 带细胞标识的比对读段、参考和覆盖，不能只有表达矩阵 | 05 的单细胞遗传变异检测：Monopogen-Indel资源核实，检测与谱系解释分开 |
| “这个蛋白会不会结合这条RNA”“结合在哪”“想找能结合它的RNA” | 明确蛋白/RNA序列或候选设计约束、可靠模型资源 | 12 的蛋白质–RNA相互作用预测与设计：分别处理配对评分、位点与生成 |
| “细胞名字对不对”“两个软件结果冲突”“疾病细胞被全标成正常” | 已注释对象、reference、marker、供体和QC | 05 的单细胞类型注释与参考映射：scDiagnostics诊断，不自动删异常或改标签 |

## 七个方法研发方向的条件接入

下列名称来自研究方案，不表示同名数据库或完整论文平台已经部署。先判断数据证据，再进入相应本地适配器；不得对“毕业/发表”一次启动全部方向。

| 口语或隐含需求 | 需要的证据 | 入口和真实执行能力 |
| --- | --- | --- |
| 这些数据适不适合、能否独立验证 | 有来源的候选元数据和预先纳排条件 | 当前Skill的数据集设计适配审计：硬条件、未知与独立性检查（OmicsDesignIndex方向） |
| 数据库更新后结论变了 | 两版结果/运行记录，或固定前景背景和两版term–gene表 | 通用Plugin的数据库版本与分析结论漂移审计：结果比较或ORA实际重算（BioDataDrift方向） |
| 随机分组也显著、需要负对照 | 可交换的供体级数值和独立/分块/配对设计 | 通用Plugin的组学负对照与假阳性校准：标签置换；模型任务另回模型评估（NullOmics方向） |
| 换队列还成立、哪阶段开始变 | 独立研究效应/SE或独立定义有序轴和供体状态值 | 单细胞跨队列整合与元分析：随机效应、逐研究剔除或探索性阶跃扫描（StateShiftAtlas方向） |
| 换邻域尺度结论就变、邻近可靠吗 | 供体、切片、细胞标签和物理坐标 | 空间转录组分析：真实重算半径网格、供体级敏感性（SpatialRobust方向） |
| 表达不变但剪接改变、异构体证据矛盾 | 已定量供体事件/异构体支持、统一注释和出处 | 可变剪接分析：供体比例及描述性区间，单细胞剪接分支条件性交接（IsoformStateDB方向） |
| 比较生信助手、检查升级回归 | 冻结案例、真实执行记录及产物 | 通用Plugin的生信分析代理可靠性评测：离线判据和产物审计（BioAgent Failure Atlas方向） |

不把七个本地任务表述为七个全功能数据库。持续索引、自动在线重放、分割模型训练、未发布算法均不是这些适配器已实现的能力。脚本执行和科学判断分开：代理负责核验输入并选择分支，用户不需要认识上述名称或填写配置。现有MCP继续承担其实际已有能力，不新增接口或绕过权限。

## 路由反例与验收

- 单个基因名或疾病名：不同时启动上述方法；先询问研究问题或读已有材料。
- 只想解释论文：解释方法与适用性，不运行流程。
- 只有表达矩阵：不能直接做 Indel；只有 peaks：不能宣称基因调控已成立。
- 只有病人预后问题：优先终点、事件数和验证队列，不为凑单细胞或新模型改变主要问题。
- 用户明确只要选数据：止于筛选与方案，不启动模型和全流程。
- 结果不显著：检查功效、偏差和假设，不能换阈值直到显著。

## 交接与返回

向专业入口交接问题、已验证文件、独立统计单位、对比、已做步骤、资源与权限边界、希望交付的证据。参数由代理根据协议和数据制定并说明依据，不要求新手预填。

返回时记录是否真正执行、可追溯表/图/日志、适用背景、未完成检查、阴性与冲突。区分描述性、关联性、预测性和因果性证据。专业能力没有安装或后端不可用时明确缺口，不能仅因为分流表有一行就声称可以运行。
