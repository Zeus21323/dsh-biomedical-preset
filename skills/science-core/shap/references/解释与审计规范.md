# 解释与审计规范

## 运行前检查

- 明确训练、验证和解释数据，不在全数据上先做特征选择。
- 记录模型版本、特征顺序、预处理器和类别编码。
- 使用 interventional 解释时，背景集从训练数据抽取，不能包含验证或测试结局信息；tree-path 路线使用模型内部路径计数，不另设背景集。
- 高相关特征需要做分组解释、置换或替代背景集敏感性分析。
- 缺失值指示变量和批次变量不得在报告中被误写为生物机制。

## 输出要求

- 区分全局平均绝对 SHAP 与带方向的个体 SHAP。
- 写明解释的模型输出尺度。
- 验证 `base value + SHAP值之和` 能重构被解释输出。
- 同时报告模型性能；解释一个表现很差的模型没有实际意义。
- 使用 interventional 路线时，对至少两个合理背景集复核主要特征是否稳定；同时与 tree-path 路线比较相关特征假设带来的变化。

## 解释边界

SHAP 解释模型，而不是自然规律。特征排名可能受到编码、共线性、采样和模型选择影响；任何因果、临床或机制结论都需要独立研究设计支持。

SHAP 官方 API：<https://shap.readthedocs.io/en/stable/api.html>

## 执行依赖

脚本需要 Python 3.12 以上，以及 `numpy`、`pandas`、`matplotlib`、`scikit-learn` 和 `shap`。应在隔离环境安装并记录解析后的实际版本；不要把这些较重依赖加入全部 Plugin 的基础运行环境。运行 `--validate-only` 只检查 CSV，不导入上述建模包。
