# 科研数据同步与系统自动化（nf-core/datasync）

## 识别数据与研究目标

从交付文件与报告中识别源位置、目的位置、操作类型、凭据引用和期望的覆盖策略；先列出将受影响的对象，区分复制、移动、删除与同步。

## 方法选择

依据选定版本实际支持的工作流组织操作，逐一确认远端可达性和目标空间；将传输计划与执行日志对应，不能把同步命令当成只读检查。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `dev`；`23f779f878624d7927169dc17d614121fe2517e0` |
| 上游维护 | 开发版本；按当前代码实际实现的范围使用 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 引擎声明 | `!>=25.10.4`；还需核验 Java、容器和 profile |

## 根据数据确定参数

从文件体积、已有目标副本、摘要和可用带宽选择并发、重试与增量策略；覆盖或删除不能从“帮我分析数据”推断授权。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |
| [输入模式-1.json](references/输入模式-1.json) | 准备 input 对应的样本表或输入文件时读取 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/datasync -r 23f779f878624d7927169dc17d614121fe2517e0 -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

比较传输前后对象数量、大小及可用校验值，检查重试和部分传输；对凭据脱敏，不在报告中保留令牌。

交付操作清单、传输结果及失败对象；公开上传、覆盖和删除必须处于用户明确授权的范围内，同步完成本身不说明科学数据有效。
