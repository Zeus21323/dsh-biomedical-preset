# 公共测序数据与元数据获取（nf-core/fetchngs）

## 识别数据与研究目标

从交付文件与报告中识别公开 accession 清单、目标数据类型、输出位置和期望关联的下游流程；区分研究、样本、实验与 run 标识。

## 方法选择

先解析元数据并检查一个样本对应多个 run、单双端与文件可用性，再按数据量规划下载；下游样本表按本版本实际支持的目标格式生成。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `1.12.0`；`8ec2d934f9301c818d961b1e4fdf7fc79610bdc5` |
| 上游维护 | 未归档；使用这里固定的源码，不自动跟随新版本 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 引擎声明 | `!>=23.04.0`；还需核验 Java、容器和 profile |

## 根据数据确定参数

从 accession 层级、单双端和多个 run 的关系构造下载清单，以真实体积决定分批与并发；不根据目录名自动合并不同生物样本。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |
| [输入模式-1.json](references/输入模式-1.json) | 准备 input 对应的样本表或输入文件时读取 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/fetchngs -r 8ec2d934f9301c818d961b1e4fdf7fc79610bdc5 -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

核查下载完整性、压缩文件和元数据一致性；缺失文件、撤回 accession、受控访问及不完整配对单独列出。

输出数据文件、来源元数据、下载记录和可用样本表；公共归档中的分组标签不自动构成可靠的病例对照设计。
