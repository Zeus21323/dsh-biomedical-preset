# ENA 测序数据提交准备（nf-core/seqsubmit）

## 识别数据与研究目标

核对交付包中的研究、样本、实验和 run 元数据、待提交文件、访问权限及目标 ENA 环境；先区分准备提交材料与实际对外提交。

## 方法选择

按 ENA 与本版本要求验证字段、样本关系和文件身份，形成可审阅的提交包；已有 accession 与新建对象分开，避免重复注册。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `1.0.0`；`717fd19e7a40099fbe5362ec48ab8ec21f62d3f8` |
| 上游维护 | 未归档；使用这里固定的源码，不自动跟随新版本 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 引擎声明 | `!>=25.10.4`；还需核验 Java、容器和 profile |

## 根据数据确定参数

根据研究、样本、实验和测序 run 的对应关系选择字段与文件拆分；技术重复保留 run 身份，准备元数据不等于已授权公开提交。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/seqsubmit -r 717fd19e7a40099fbe5362ec48ab8ec21f62d3f8 -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

检查必填字段、受试者隐私、文件校验和、上传完整性及服务器回执，记录部分失败和重试范围。

交付提交材料、检查结果或已授权提交的回执；没有明确上传/发布授权时停留在本地准备，不把 accession 返回等同于数据已经公开。
