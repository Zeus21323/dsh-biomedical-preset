# 交互式写作流程

## 从研究方向开始

没有现成草稿时，先从用户消息、附件、题目和既有会话中归纳三个核心要素：

1. **研究对象**：具体研究什么现象、变量、系统、过程或疾病机制？
2. **核心矛盾**：现有认知或方法在什么具体场景中不够用？
3. **研究切入点**：拟从什么角度突破？

不要把这三个要素变成固定问卷。能够合理推断时，写入项目简报并继续；不确定但不影响结构时标记“待确认”。只有存在多个会改变核心论证的候选方向时，才调用 `ask_user`，把基于现有材料生成的 2–4 个具体候选方向作为选项。

如要完成整份申请书，同样先提取申报类别/指南、已有基础和预期研究周期。缺失字段使用保守默认值或占位，不逐项追问。用户没有指定交付范围且无法从请求判断时，可通过一次 `ask_user` 选择“当前章节修改”“完整初稿”“逻辑诊断”或“模拟评审”；已明确时不得再问。

## 立项依据开头

根据归纳后的信息撰写三段：

- 第一段：研究对象在具体场景中的重要性，以该场景的困难收束。
- 第二段：概括现有方法已经解决的问题，再指出与核心矛盾直接相关的局限。
- 第三段：明确点名核心矛盾，用“由此，本项目拟……”引入项目思路。

每段通常 3–5 句，不添加多余小标题。事实性表述需要文献时标记引用位置，不要生成虚构文献。

完成后自行检查问题界定、遗漏、夸大和最薄弱环节，在交付中直接报告；不要用这些问题阻断后续写作。

## 其他章节

写作前在内部确定该章任务和关键论点，然后直接成文。需要让用户理解结构时，可在正文前展示一行“本章任务”，但不得要求逐章确认。

- **研究现状**：围绕问题和证据组织，不按作者逐篇罗列。
- **研究内容**：写清每部分解决什么、为何需要、产出什么，以及与下一部分的关系。
- **研究目标**：可验证、可完成，并与研究内容逐项对应。
- **关键科学问题**：表达真正未知的机制或规律，不把技术步骤包装成科学问题。
- **技术路线**：说明方法、数据/样本、对照、评价指标、风险与替代方案。
- **创新点**：说明相对已知工作的增量、为何重要，以及项目如何验证该增量。

用户要求完整初稿时，按计划连续完成各章，不在章间调用 `ask_user`。只有后续章节依赖一个尚未决定且会改变核心研究设计的互斥选择时，才合并为一次结构化选择。
