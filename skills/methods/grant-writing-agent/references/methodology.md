# 中文基金申报书方法论

## 核心原则

### 问题驱动

每一段都应回答一个具体矛盾。先解释现有认知或方法为何在目标场景中不够，再说明项目如何针对这一缺口开展研究；不要从模型结构、算法名称或公式开始。

### 立项依据三段式开头

1. 说明研究对象的重要性及目标场景为何困难。
2. 先肯定现有工作的贡献，再指出它在该具体问题上的局限。
3. 用一句话收束核心矛盾，再以“由此，本项目拟……”引出研究思路。

避免以“随着……的发展”作为空泛开场。局限必须建立在准确概括现有工作的基础上。

### 递进式研究内容

研究内容应构成问题链：

1. 第一部分解决核心建模、认知或机制问题，形成主干结果。
2. 第二部分承接第一部分，解决主干结果在真实约束下成立的问题。
3. 第三部分把前两部分转化为可验证、可解释或可应用的结果。

第二、三部分应明确说明依赖上一部分的何种产出。不要机械套用三部分；指南、科学问题或项目规模不适合时，以实际需求为准。

### 研究目标与科学问题

- 研究目标使用可检验的陈述句，写明对象、要建立的能力、要突破的瓶颈和可评价结果。
- 关键科学问题聚焦未知规律、机制或因果关系，用问题形式表达，避免把工程任务改写成问句。
- 研究内容、目标、科学问题和技术路线之间必须能够逐项对应。

### 技术路线

每个技术部分采用：问题背景 → 方法设计 → 验证方式 → 预期结果。公式前说明引入原因，公式后解释符号和它如何支撑研究目标。

## 常见问题

| 问题 | 表现 | 修复方向 |
|---|---|---|
| 技术堆叠 | 罗列模型、数据库或实验手段 | 回到每项技术解决的具体矛盾 |
| 研究内容与技术路线重复 | 两处都写操作步骤 | 内容写做什么和为什么，路线写怎么做和怎么验证 |
| 研究内容相互并列 | 三部分互不依赖 | 写清输入、产出和承接关系 |
| 结论跨度过大 | 从相关性直接推出机制或应用价值 | 降低结论强度或补充验证环节 |
| 大同行难以理解 | 缩写、术语和背景缺失 | 首次出现时定义，并补充必要桥接句 |
| 目标不可评价 | 使用“深入揭示”“系统阐明”但无指标 | 增加可观察终点、比较对象和成功标准 |
