# 论文审稿

## 核心规则

使用这个 skill 的模型必须自己完成审稿推理。不要为学科分类、章节评审、参考文献解析或最终评分调用其他 LLM/API。只有需要外部证据时才调用搜索工具：用 `web search` 核验公共事实、法律政策、事件、数据集和日期；用 `academic/paper search` 核验论文、引用、出版元数据和参考文献真实性。

## 工作流

1. 读取论文并保留可追溯位置。提取题名、摘要、大纲、段落/页码索引、表格、图片、图注和参考文献。若输入已经是纯文本，保持稳定的段落编号。
2. 先识别参考文献区间，再把正文和参考文献列表分离；逐章审稿时不要把参考文献列表当作正文内容。
3. 搜索可用时核验参考文献。把每条参考文献解析为题名、作者、年份、来源/`DOI` 等信息；优先调用 `academic/paper search`，学术搜索失败或条目不是学术论文时再调用 `web search`。标记未验证、低置信度、题名/作者/年份不一致、撤稿和疑似重复文献。
4. 在正文部分识别章节区间。除非用户特别要求，跳过作者信息、目录、致谢、附录、脚注和参考文献等非审稿主体。摘要和引言主要检查事实性声明、清晰度、夸大表述和明显事实错误。
5. 将论文归类为：艺术学、教育学、经济学、法学、民族学、理学、工学或其他。依据摘要、大纲、章节标题和正文内容判断，并在逐章审稿和终评中应用下面的学科检查点。
6. 逐章评审主体章节。每章给出 1-10 分、优点、缺点和段落/页码锚点。重点检查事实矛盾、逻辑断裂、无依据声明、方法不清、实验/数据薄弱、图表错误、文字错误、引用误用和跨段落不一致。
7. 有选择地搜索。遇到可疑事实声明、法律规范、公共事件、数据集、指标或文献综述声明时，调用当前 agent 可用的 `web search` 或 `academic/paper search` 工具。不要编造搜索结果；没有搜到证据时，表述为“公开/学术搜索未能验证该说法”，不要直接断言为假。
8. 基于章节评审和参考文献核验生成终评，不要简单平均章节分数。大量低级错误、疑似伪造参考文献、参考文献验证率低、严重方法缺陷或证据冲突，都应降低最终评分。

## 学科检查点

### 艺术学

检查艺术理论/艺术形式介绍是否足以支撑后续分析，而不是泛泛铺垫；艺术形式介绍章节是否配备图片、图版、作品样例或可观察材料展示艺术形式，避免只用抽象文字空谈；理论与形式的结合是“嫁接”（贴标签）还是“化合”（理论真正改变了对形式的观看方式），推导链是否显式；涉及非遗/传统艺术时，是否区分“原生语境”与“当代展演/舞台化语境”，避免把某一时期风格本质化；涉及设计实践时，是否提供过程性材料，如草图、迭代版本、技术参数，最终效果是否对应前期分析；借用叙事学、人类学、管理学等跨学科理论时，概念是否经过学科转换，而不是直接移植。

常见缺陷包括：理论段落与形式分析段落脱节，中间缺少推导过渡；跨文化/跨媒介比较单位错配，如整体画种与具体流派直接比较；声称“传统”“自古如此”但缺少断代证据；“填补空白”“提供新思路”等价值判断没有具体化空白位置或思路路径。

### 教育学

检查教育理论介绍是否能支撑后续分析，而不是和正文脱节；教学场景是否真实、具体且前后一致，学校匿名化不等于不真实，重点看人数、学科、课程、年级、教学持续时间、评价方式等细节是否自洽；问卷或实验环节是否给出具体问卷内容、发放与回收情况、结果数据、信度/效度分析和结果解释。若只有“进行了问卷调查”但无问卷内容、结果或可信度分析，应明确指出证据不足。

### 经济学

检查模型前提假设是否明确，假设是否匹配现实情境和研究对象特征；经济理论推导是否正确，理论适用边界是否交代，理论与研究对象是否匹配；研究对象和数据章节是否说明权威来源、样本选择标准、数据处理与清洗方法；实证结果或数值模拟章节是否存在计算错误、数值量级不合理、与常识/市场数据冲突、缺少稳健性检验等问题。

### 法学

核验法律规范是否存在、条文引用是否与原文一致、当前是否仍然有效；合理区分“法律变迁中介绍旧法”和“用已失效旧法作为现行依据”，后者应作为问题指出；核验案例是否存在、案例事实和判决观点是否被准确介绍、案例是否支持论文观点；检查法学概念是否混淆，引用的学说是否存在，法律术语是否规范，法律三段论推理是否清楚。

### 民族学

检查田野调查过程是否交代清楚，调查对象是否覆盖多种角色，调查描述是否真实自洽；民族志介绍是否深入，是否能剖析表象背后的象征意义与社会功能；是否尊重文化解释边界，避免猎奇化、刻板化或本质化表达；检查隐私保护、敏感议题处理和研究伦理；注意术语准确性，例如不要混用民族、族群、社区等概念。

### 理学/工学

检查相关工作是否与论文领域匹配，是否遗漏关键相关工作；方法部分是否可信，推导过程是否正确，实现细节是否足以复现；实验设计是否有说服力，数据集、样本划分、预处理、超参数、对照组、消融实验、指标定义和重复实验是否写清；实验分析是否对应实验结果，结果是否能支持论文观点；若实验结果曲线、数值或趋势明显不支持作者结论，例如结果明显不是线性关系却声称线性关系，应直接指出。

### 图审/Graph Review

优先检查方法-实验-结果-结论是否闭环；图表的坐标轴、单位、图例、编号、标题、公式符号和正文是否一致；曲线趋势、数值量级、百分比与绝对值是否互相矛盾；单一数据集或单一场景的结果不要被写成普适结论；基线和引用是否完整、公平，是否遗漏关键相关工作，是否把他人成果写成自己的；如果正文、表格、图注、结论之间互相冲突，要直接指出具体冲突点。

## 审稿边界

- 不要惩罚明显的解析问题，例如换行断词、公式乱码、版式丢失或公式渲染异常，除非源文档本身明确存在该错误。
- 不要要求摘要、引言、相关工作或结论提供通常属于方法/实验章节的实现细节。
- 不要把已经验证通过的参考文献说成不存在。对于已验证文献，只检查论文是否准确描述和使用它。
- 谨慎处理日期。过去年份不代表“未来事件”。只有具体日期晚于当前日期，或文本把尚未可能发生的事情描述为既成事实时，才指出时间冲突。
- 评论必须可执行并有位置锚点。缺点描述不要暴露内部 index；最终回复中优先使用段落号、页码或章节位置。

## 输出格式

除非用户要求其他语言，默认用中文输出结构化审稿结果：

```json
{
  "paper_title": "",
  "subject": "艺术学|教育学|经济学|法学|民族学|理学|工学|其他",
  "reference_verification": {
    "summary": "",
    "verified_count": 0,
    "problematic_references": [
      {"reference": "", "issue": "", "evidence": ""}
    ],
    "duplicate_references": []
  },
  "chapter_reviews": [
    {
      "chapter_title": "",
      "score": 1,
      "strengths": [{"point": "", "location": ""}],
      "weaknesses": [{"point": "", "location": "", "evidence": ""}]
    }
  ],
  "final_evaluation": {
    "final_score": 1,
    "summary": "",
    "overall_strengths": [],
    "overall_weaknesses": [],
    "recommended_decision": "accept|minor revision|major revision|reject|not specified"
  }
}
```

如果用户要求自然语言而非 JSON，也保留同样的信息结构：参考文献核验、逐章评审、最终评分、主要优点、主要缺点和修改优先级。
