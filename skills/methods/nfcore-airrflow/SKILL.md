# BCR与TCR免疫受体库分析（nf-core/airrflow）

## 识别数据与研究目标

从交付文件与报告中识别受体库 reads、链类型、协议、UMI 和样本信息，核对胚系库与物种，区分 bulk 和单细胞输入。

## 方法选择

按 Immcantation 及本版本支持路径完成受体重排注释、去重、克隆划分和适用下游，保留克隆定义。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `5.1.1`；`8bc3e567d0bb3a4c47ead15a8f42e764580f76dc` |
| 上游维护 | 未归档；使用这里固定的源码，不自动跟随新版本 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 引擎声明 | `!>=26.04.1`；还需核验 Java、容器和 profile |

## 根据数据确定参数

按链类型、UMI 设计、胚系库与距离分布选择去重和克隆划分；跨样本比较控制深度与采样差异，不能把同一克隆阈值无条件用于所有受体和物种。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |
| [输入模式-1.json](references/输入模式-1.json) | 准备 input 对应的样本表或输入文件时读取 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/airrflow -r 8bc3e567d0bb3a4c47ead15a8f42e764580f76dc -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

检查有效重排、productive 状态、V/J 指派、CDR3 和测序深度，BCR 还需考虑体细胞高突变。

交付 AIRR 注释、克隆与多样性结果；克隆扩增不能单独推断抗原特异性，链配对信息不能凭空补全。
