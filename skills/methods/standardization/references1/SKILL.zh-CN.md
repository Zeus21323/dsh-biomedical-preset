# Standardization 中文版

使用本 skill 来规范需要 `browser_use` 远程浏览器流程的研究任务。本 skill 定义来源选择和研究流程；具体浏览器操作规则来自 remote-browser skill。

## 必须配合使用的 Skill

使用浏览器工具前，先读取并遵循：
`browser_use` 的相关搜索规定，然后再满足本skill的相关约束

遵循其中关于 `mcp_remote_browser_*` 工具的生命周期规则：先列出设备，创建任务专属 session，打开重复标签页前检查已有标签页，优先使用结构化元素 ref，对敏感操作请求用户批准，并在浏览器工作结束前 finalize tabs。

## 研究流程

1. 搜索前先判断用户请求类型：
   - 生物医学或生命科学：医学、疾病、药物、临床试验、基因、蛋白、通路、物种、流行病学、公共卫生、生物技术、诊断、医疗器械、患者照护或实验方法。
   - 通用研究：政策、产品、公司、市场、技术、文档、新闻或其他非生物医学主题。
2. 对生物医学或生命科学请求，必须优先检索 PubMed：
   - 从 `https://pubmed.ncbi.nlm.nih.gov/` 开始。
   - 当任务需要文献发现、引用脉络或更广覆盖时，如果浏览器/工具能力允许，应并行检索 PubMed 和 Google Scholar。PubMed 仍是生物医学证据的主来源；Google Scholar 是高优先级并行来源，用于查找引用链、高引用论文、全文入口和跨学科版本。
   - 使用科学术语、同义词、缩写和用户请求中的关键实体构造检索式。
   - 在相关场景下优先选择近期综述、系统综述、Meta 分析、临床指南、随机对照试验和高质量原始研究。
   - 使用文章页面、摘要、发表日期、期刊名、PMID/DOI，以及可用的全文链接。
   - 不要过度关注导航栏、页脚、推荐文献、作者链接、期刊链接、相关文章组件、指标组件、分享链接等页面无关内容；重点关注有用的文章元数据，并认真阅读相关摘要。
   - 为了提高第一轮响应速度，除非用户一开始明确要求下载，否则不要直接下载论文。先识别并总结最相关的文献，然后询问用户是否需要下载全文。
   - 用户允许后，在访问权限允许且文献高度相关时，把完整论文下载到工作区，并通过平台的用户可见文件/产物机制把同一篇文献提供到对话区；如果下载不了，需要向用户说明具体原因。
   - 当用户明确要求下载文献时，两个位置都必须完成：文件保存到当前工作区，同时在对话区展示/提供同一文件。不要把浏览器标签页、来源 URL 或只有元数据的引用当作已完成下载。
   - 要仔细看高引用文章并优先关注顶刊文章，但不要只按引用量或期刊名排序。
   - 只有在检查 PubMed 后，或 PubMed 明显不适用时，才转向 Google Scholar、知网出版社页面、临床指南网站、监管来源或普通网页搜索。
   - 如果普通检索未找到结果，应该在pubmed界面进行高级检索；并配合pubmed界面的常见问题解答和用户指南辅助用户问题的回答。
3. 对非生物医学请求，优先选择权威一手来源：
   - 官方文档、标准组织、政府或监管机构页面、公司官网、原始论文、数据集或源码仓库。
   - 二级来源只用于定位方向或交叉核验；如果存在一手来源，不要只依赖二级来源支撑事实性结论。
4. 对当前性强、影响大、有争议或容易变化的说法，进行多源核验：
   - 确认日期、版本、作者、司法辖区和定义。
   - 区分已被来源直接支持的事实和推断。
   - 当来源相互冲突或证据有限时，明确说明不确定性。
5. 收集足够的文献和来源元数据，保证答案可追溯：
   - PubMed 来源：标题、必要时列作者、期刊、年份/日期、PMID、可用 DOI 和 URL。
   - 网页来源：页面标题、发布方/机构、URL、可见的发布日期或更新日期，以及与访问相关的上下文。
6. 综合归纳，不要大段粘贴：
   - 不要直接倾倒完整页面快照或长摘要。
   - 用用户请求的语言总结发现。
   - 尽可能附上来源链接和标识符。

## PubMed 检索建议

对生物医学任务，先使用适合 PubMed 的检索式，再考虑普通网页搜索：

- 疾病或干预：`condition AND intervention`，再按需要加入 `systematic review`、`meta-analysis`、`randomized controlled trial` 或 `guideline` 等研究类型词。
- 基因或蛋白：包含官方符号和常见别名；必要时加入物种或疾病语境。
- 药物或化合物：包含通用名；相关时加入商品名、机制词、不良反应或临床试验阶段。
- 诊断或生物标志物：组合目标疾病、检测/试验名称，以及 `sensitivity`、`specificity`、`validation` 或 `cohort` 等词。
- 近期证据：只有在时效性重要时，才使用 PubMed 过滤器或发表日期相关检索词。

## PubMed/PMC 开放获取下载流程

当用户要求下载生物医学文献时，避免陷入无休止 API 重试。使用下面固定路径：

1. 开放获取发现优先走 PubMed/PMC 的 NCBI E-utilities：
   - 用户要求可下载/开放获取论文时，PubMed 检索式加入 `free full text[filter]`。
   - 使用 `esearch.fcgi`，参数包含 `db=pubmed`、`retmode=json` 和 URL 编码后的 `term`。
   - PMID 到 PMC 的映射要批量走 `elink.fcgi`，参数使用 `dbfrom=pubmed`、`db=pmc` 和逗号分隔的 PMID。除非 PMID 少于 5 个或批量重试确有必要，不要逐个 PMID 查询。
   - 拿到 PMCID 后，优先尝试 PMC PDF URL 模式：`https://pmc.ncbi.nlm.nih.gov/articles/<PMCID>/pdf/`。
2. Europe PMC 只作为回退：
   - 先用简单查询，例如 `<主题词> HAS_PMC:Y`、`format=json` 和适中的 `pageSize`。
   - 如果 Europe PMC 查询/过滤语法连续失败两次，停止修过滤器或 URL 编码，改回 NCBI E-utilities 或 PubMed/PMC 浏览器路径。
   - 两次失败后，不要反复输出“过滤器语法有问题”“URL 编码有问题”“改用正确 API 参数”。应报告失败原因并切换到下一条路径。
   - 如果 Europe PMC 的 `Open PDF` 或 `https://europepmc.org/api/getPdf?pmcid=<PMCID>` 返回 404、HTML、登录/错误页或任何非 `%PDF-` 响应，应把该 PMCID 的 Europe PMC PDF 路径标记为失败。不要继续重试同一个端点。
   - 不要用 NCBI `efetch` XML、Europe PMC XML、JATS XML、HTML 全文、摘要或元数据替代出版社/PMC 原始 PDF。只有当来源明确允许全文访问/下载，或 API 以开放全文记录提供该内容时，才可以保存 XML/HTML 作为辅助全文，并必须明确标注。
   - 最后兜底的转换版 PDF 路径：如果开放获取文章的所有真实 PDF 路线都失败，但允许下载/保存的全文 XML/HTML 可用，应询问用户是否接受明确标注的转换版 PDF。如果用户已经要求“只要可读 PDF 都可以”或明确接受转换，可以从 XML/HTML 生成转换版 PDF，并在文件名和报告中标注 `converted_from_xml` 或 `converted_from_html`。
   - XML/HTML 全文使用权限门槛：下载、保存或转换全文前，必须确认条目是开放获取，并且全文由 PMC/Europe PMC/NCBI 或其他允许全文访问/下载的来源提供。清单里要记录证据，例如 PMCID 且 PMC 有全文、Europe PMC 的 `isOpenAccess`/license 字段、Creative Commons/许可证声明，或官方 OA 全文端点。如果出版商/来源禁止全文下载、阻止程序化获取、缺少开放许可证，或只允许网页浏览，不要下载或转换全文；只报告限制原因并提供元数据/链接。
   - 转换版 PDF 不是原始下载论文 PDF。绝不能把 XML/HTML 转 PDF 产物说成出版社/PMC 原始 PDF。元数据中保留 XML/HTML 来源 URL/PMCID，并说明版式、图表、公式、特殊字符可能缺失、归一化或不完整。
3. 浏览器回退：
   - 如果 API 调用超时或两次聚焦尝试失败，使用 PubMed 网页的 Free full text / Free PMC article 筛选，打开 PMC 文章页，再使用页面可见 PDF 链接。
   - 除非用户明确要求更大的集合，否则只打开最相关的 1-5 篇。
4. 完成标准：
   - 只有实际 PDF 已保存到工作区，并在对话区提供同一文件，才算下载完成。
   - 如果只拿到 PMID/DOI/PMCID 元数据或浏览器标签页，只能报告“已找到元数据”，不能报告“已下载论文”。
   - 如果只拿到 XML/HTML 全文，只能报告“已找到 XML/HTML 全文”，不能报告“已下载原始 PDF”。转换版 PDF 只能按最后兜底路径交付，并必须标注为转换版。
   - 如果没有无需登录或订阅即可访问的 PDF，说明访问受限，并保留文献元数据。
5. 防止白忙活的失败保护：
   - 不要假设 `https://pmc.ncbi.nlm.nih.gov/articles/<PMCID>/pdf/` 一定是有效 PDF URL。应先打开 PMC 文章页，并在页面中提取真实 PDF `href`（如果存在）。
   - PMC 文章页中的 `<meta name="citation_pdf_url" ...>` 要视为真实 PDF 候选来源，即使 `interactive_elements` 里没有可见 PDF 按钮。还要检查 `<a href*="/pdf/">`、`<link>` 和其他类似 PDF 的 DOM/链接目标，并基于文章页补全相对 URL。
   - 如果已经找到 `citation_pdf_url` 或其他真实 PDF 候选，不要因为 `interactive_elements` 太杂、参考文献链接太多或没有可见按钮，就继续反复寻找可见 PDF 按钮。应使用已提取 URL 进入下载和校验步骤。
   - 如果命令行 `curl`/脚本下载 PMC PDF URL 返回很小的非 PDF 响应，例如约 1.8 KB HTML，不要继续批量 curl 下载，也不要重新进入同一个“寻找可见 PDF 链接”的循环。应只针对该候选通过当前浏览器上下文重试：使用已有文章页/session，在新标签页打开已提取 PDF URL，或从文章页触发一个 `<a download>` 点击，然后检查最终 URL 和保存字节。
   - 如果浏览器导航到已提取 PMC PDF URL 后重定向回文章页或返回 HTML，应把它记录为该条目的具体 PMC/浏览器访问失败。不要反复重读本 skill，也不要反复搜索同一个 DOM。可用时报告最终 URL、状态码、Content-Type，并保留 PMC HTML 全文链接。
   - 如果 `efetch` 使用 `rettype=pdf` 仍返回 XML 或任何非 PDF 字节，应把该端点的原始 PDF 获取判定为失败。先回到 PMC/Europe PMC/出版社页面的真实 PDF 候选。只有真实 PDF 路线都失败后，才允许使用最后兜底的转换版 PDF 路径。
   - 转换版 PDF 生成约束：使用支持 Unicode 的字体，或在清洗不支持字符时给出警告；首页包含标题、作者、期刊/年份、PMID/PMCID/DOI、来源 URL、允许全文使用的证据，并写明“Converted from XML/HTML; not publisher PDF”；校验输出能打开且以 `%PDF-` 开头；在工作区同时保存转换版 PDF 和允许保存的 XML/HTML 源文件或元数据清单。
   - 批量下载前，先为每篇收集 PMCID、文章 URL、提取到的 PDF 候选 URL 和提取来源（`citation_pdf_url`、anchor href、可见按钮）。只下载有 PDF URL 的候选，逐篇校验保存文件；如果出现重复非 PDF 模式，立即停止批量。
   - 每次下载 PDF 后，都要同时校验响应元数据和文件内容：跟随跳转；如果能拿到 Content-Type，应是 PDF 类型；保存文件必须以 `%PDF-` 开头；拒绝很小的 HTML/错误页响应。
   - 如果任一 PDF 下载得到 10 KB 以下的非 PDF 响应（例如 1.8 KB 的 HTML/错误页），立即停止批量下载。先对一个失败样本诊断：查看 `file` 结果、前 500 字节、最终跳转 URL 和 HTTP 状态，再决定下一步。
   - 如果连续两个 PMCID 下载出现相同的非 PDF 大小或相同错误特征，不要继续跑完剩余批次，也不要盲目切换 API。应报告共同失败模式，并改为解析文章页 PDF 链接，或向用户报告可用元数据/HTML 全文链接。
   - 如果 PMC 文章页没有 PDF 链接，报告“可免费阅读全文，但未找到 PDF 下载链接”，并提供 HTML 全文 URL；不要把它标记为已下载 PDF。
   - 出现重复非 PDF 模式后，不要继续反复输出“切换 API”“修复 URL 编码”“使用正确过滤器”。应说明具体失败原因，然后停止或切换到有边界的回退路径。

## 并行检索建议

使用并行检索来减少等待时间并提高覆盖面，但要保持证据优先级清楚：

- PubMed + Google Scholar：生物医学文献发现时，尽可能并行检索。PubMed 用于生物医学索引、摘要、医学术语、PMID/DOI 元数据和研究类型过滤；Google Scholar 用于引用量、高引用论文、全文入口、预印本和跨学科/出版社版本发现。
- PubMed + 指南/监管来源：当用户询问临床实践、安全性、诊断、治疗或政策时，可并行检索。建议和规范性结论优先看官方指南/监管来源，文献证据看 PubMed。
- PubMed + 知网：只有当生物医学问题明确涉及中文文献、中国临床研究或中国语境时，才并行检索。
- 不要让并行检索造成重复工作。总结前按标题、DOI、PMID、试验编号和作者/年份去重。
- 如果并行来源结论冲突，要说明冲突，并按不同 claim 类型选择最权威的来源。

当用户提出类似临床或医疗建议的问题时，将回答定位为信息性研究。不要把诊断或治疗建议表达成针对个人的医疗意见。

## PubMed 页面处理效率规则

PubMed 和出版社页面通常包含大量无关内容，例如导航栏、页脚、推荐文献、作者主页链接、期刊链接、相关文章组件、指标、引用工具、分享链接和服务链接。不要在这些内容上消耗过多注意力。

提取文章结果时按以下顺序处理：

1. 先调用 `interactive_elements`。
2. 如果 `interactive_elements` 中没有文章标题链接或文章操作控件，不要立刻完整分析整个 snapshot。
3. 调用 `snapshot` 或 `page_info`，但如果工具支持，要限制 `max_chars`。
4. 在返回内容里搜索用户关键词、文章标题、`Abstract`、`PMID`、`DOI`、`Journal`、`Free full text`、`Full text links` 和 `Similar articles`。
5. 认真阅读有用的摘要，用摘要判断相关性、研究类型、人群/模型、干预/暴露、结局、方法和局限。
6. 忽略作者链接、期刊链接、指标链接、推荐链接、服务链接、导航链接和页脚链接，除非它们对当前任务确实必要。
7. 必要时只打开最相关的 1-5 篇文章。

## 浏览器操作模式

配合 remote-browser skill 使用以下模式：

1. `mcp_remote_browser_list_devices`
2. 创建或复用一个任务专属 `session_id`。
3. `mcp_remote_browser_name_session`
4. `mcp_remote_browser_user_tabs`，避免打开重复标签页。
5. 打开或 claim 目标标签页。
6. 搜索、检查结果、打开来源页面并收集来源元数据。
7. 只有在需要视觉证据或用户要求产物时，才使用截图或导出页面。
8. 结束前执行 `mcp_remote_browser_finalize_tabs`。

对于简单线性搜索，优先使用带白名单动作的 `mcp_remote_browser_run_action_plan`。对于探索式研究，使用单个结构化工具逐步操作，确保每一步决策都基于实际观察到的页面状态。

## 输出标准

提供简洁的研究答案，包含：

- 先给直接答案或结论。
- 按来源类型或主题组织关键证据。
- 附来源链接和标识符。
- 说明重要限制、冲突或与日期相关的注意事项。
- 说明使用了哪些并行检索，例如 PubMed + Google Scholar，以及为什么使用。
- 输出最贴近用户问题的相关文献。
- 最后询问用户是否需要下载最相关文献全文，除非用户已经明确要求下载。

对生物医学答案，明确说明是否已优先检索 PubMed。如果未使用 PubMed，说明 PubMed 不适用或不可用的原因。
