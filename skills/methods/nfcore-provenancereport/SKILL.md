# 工作流来源与运行证据报告（nf-core/provenancereport）

## 识别数据与研究目标

从现有材料整理已有运行的引擎记录、软件信息、输入身份、参数及报告位置，区分观察到的事实与无法恢复的字段。

## 方法选择

按流程要求整理来源记录并生成 provenance 报告；对缺失版本或输入摘要保留未知，不根据目录名补造执行历史。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `dev`；`f0c81e35772e160e2c762a86be7f4539e1e7c944` |
| 上游维护 | 开发版本；按当前代码实际实现的范围使用 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 引擎声明 | `!>=25.10.4`；还需核验 Java、容器和 profile |

## 根据数据确定参数

按可读日志、参数文件与实际产物确定报告粒度；缺失值保持未知，不能把软件默认值回填成当时实际使用的设置。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |
| [输入模式-1.json](references/输入模式-1.json) | 准备 input 对应的样本表或输入文件时读取 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/provenancereport -r f0c81e35772e160e2c762a86be7f4539e1e7c944 -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

核对记录能否对应同一运行、时间和配置，识别重复 run、相互矛盾的软件版本与失效产物链接。

交付可追踪的运行证据报告及缺口；来源报告不替代 assay 质控或统计学证据，也不应为了补报告重跑科学分析。
