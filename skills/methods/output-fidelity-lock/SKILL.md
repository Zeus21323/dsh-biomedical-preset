# 术语与数据输出保真锁定

## 这是一条底线，不是一个可选步骤

代理写出来的每一个基因名、编号、数值和表格单元都是重新生成的，不是复制的。上下文越长、输出越长，变形越多：Ensembl 编号丢版本号、Lgals1 和 Lgals3 的 FC 互换、FDR 从 6.84e-9 变成 6.84e-8、译文里整段数据消失、NA 被填成 0、凭空出现一个看起来合理的编号。用户不会说“请帮我保真”，他们只会在拿到结果后发现对不上。所以只要输出里出现来自输入的具体内容，本 Skill 就生效；来源可以是用户消息，也可以是当前任务里代理从附件读取并登记的内容。

完整规则、四层结构、数值等价规则和两种模式见[输出保真契约](references/输出保真契约.md)；需要判断某个写法是否本来就规范时读[命名规范速查](references/命名规范速查.md)。识别规则集中在 `references/不变量模式.json`，由 `scripts/fidelity_lock.py` 读取，代理不需要把模式或任何词表读进上下文。

## 校验的是绑定关系

清单不是值的集合，而是“实体 → 字段 → 值 → 定位”的事实：`Lgals1 → fc → 43.69`。所以两个基因数值互换、译文删掉全部数据、保护标记位置互换，都会被抓出来；正式问题只包含数据错误，大小写、连字符、希腊字母、氨基酸记法这类形式差异只作警告。

## 两档处理

- 少量事实（几个基因名、几个数值、一句结论）可以直接写，但交付前必须通过校验。
- 批量数据（表格、列表、超过 10 个数据点）不允许手写。在 Markdown 中写插槽 `{{table:文件:行数:列名,列名}}`、`{{rows:文件:键列:值1,值2}}`、`{{value:文件:键列=键值:目标列}}` 或 `{{file:文件}}`，由脚本从源文件原样填充；代理只写叙述。

## 工作流

所有命令只依赖 Python 3.12 标准库，只处理可解码文本，输入只读，输出写到用户工作区，已存在的文件默认不覆盖。

1. 登记来源并提取事实清单。用户消息、上传文件、上游结果表都是来源。PDF、DOCX、XLSX 先由代理读取生成带页码、段落号、表格行列号的文本投影，再登记；读不出来的页面或图片表格必须登记为不可校验：

   ```bash
   python scripts/fidelity_lock.py extract 用户消息.txt deg_results.tsv --output 工作区/manifest.json
   python scripts/fidelity_lock.py extract 论文投影.md --projection-of paper.pdf --unverifiable "第3页表2为图片，无法投影" --output 工作区/manifest.json
   ```

   CSV/TSV 按行提取主键实体、别名列和每个数值列的绑定；纯文本按句提取实体与最近的字段标签和值。清单是唯一真值，登记后不得替换；之后引用任何事实都从清单或源文件取。

2. 生成输出。叙述部分自己写；数据部分写插槽后运行：

   ```bash
   python scripts/fidelity_lock.py render --template 工作区/report.template.md --output 工作区/report.md
   ```

   插槽引用的文件不存在、列名不对、键值不唯一时脚本拒绝写出，不会静默留空。

3. 翻译、转写或改写时不变量不进入被重写的文本。先保护，完成后回填：

   ```bash
   python scripts/fidelity_lock.py protect --input 原文.md --output 原文.protected.md --mapping 原文.map.json
   python scripts/fidelity_lock.py restore --input 译文.protected.md --mapping 原文.map.json --output 译文.md
   ```

   `⟦INV0001⟧` 形式的保护标记必须原样保留且不得互换位置；回填会核对每个标记的次数和实体—值绑定，缺一个、多一个或换了位置都不通过。语序调整而绑定不变可以通过。

4. 交付前重新读取最终产物形成候选文本再校验，不校验生成前的草稿。翻译、转写、改写用默认的 `translate` 模式；分析报告用 `analysis`：

   ```bash
   python scripts/fidelity_lock.py verify 工作区/译文.md --manifest 工作区/manifest.json --report 工作区/fidelity.json
   python scripts/fidelity_lock.py verify 工作区/report.md --manifest 工作区/manifest.json --mode analysis --allow-novel 工作区/新结果.txt
   ```

   报告项包括数值绑定到错误实体、绑定值改变、精度被改动、来源数据丢失、来源实体丢失、候选稿未包含任何来源数据、来源中不存在的数值或编号、版本号丢失或改动。输出本身是表格时加 `--table-source 源表.tsv --key-column gene_id`，会逐格对比并报告丢行、新增行、重排、单元格改动和缺失值填补。退出码 1 必须修改后重新校验；退出码 3 表示已校验范围无错误但存在不可校验范围，交付说明必须明示。

## 代理的专业判断

- `translate` 模式禁止 `--allow-novel`：译文不得引入来源里没有的数据，来源数据丢失也是错误。分析任务里校验器报“来源中不存在的数值或编号”时，先分辨是本次分析真实产生的新结果还是凭印象写的：前者要能指向产生它的文件再登记，后者删除或重新读源文件。不能为了让校验通过而登记自己说不清来源的值。
- 独立的纯整数允许阿拉伯数字、中文数字、英文数字词互换（36 只小鼠与 thirty-six mice）；科学小数、精度、正负号、指数、比较符、百分号、单位和绑定不放宽。
- 图表、章节、方法编号（表 2、Fig. 3B、方法 4.8）不是数据，校验器只记录不比较；`itself`、`Methods`、`Total` 一类普通词不作为实体。
- 用户明确要求四舍五入、换单位、统一命名时可以做，但输出要写明变换方式，原值仍应在附表或说明中可查。
- 遇到看似普通单词的符号（CAT、MET、SHH、WAS、REST、SET），看它在来源中的位置：在基因列、“基因 X”句式或与其他基因并列时按标识符处理，不翻译。拿不准时保留原样并标注。
- 记不清的值写 `[UNVERIFIED]` 或回去读文件，永远不用一个看起来合理的数填上。

## 边界

本 Skill 不判断科学结论是否正确，只保证输出与来源一致。它不解析 PDF、DOCX、XLSX 二进制文件，投影质量由代理负责并如实登记覆盖范围。模式文件按格式识别编号，不能识别全部物种的所有基因符号；漏识别意味着少一层保护，不意味着可以改写。运行时若已有独立的数据校验工具，本 Skill 的 protect、restore、render 作为生成保护层放在它之前，verify 的结果与它并列，不替代它。
