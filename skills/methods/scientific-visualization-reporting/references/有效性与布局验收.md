# 从数据到解释的通用验收

适用于统计图、空间/网络图及机制示意图，不以具体图名决定是否检查。对当前任务适用的关系执行核对；不适用项说明理由，不能虚构统计信息。

## 先建立最小事实依据

从源表、分析对象及元数据取得：问题与观察单位、实体ID及显示名、变量含义/单位、变换与筛选、比较/参考方向、分母或区间定义、已有检验及证据层级。按图的需要记录，复用现有配置和运行记录，不为每图另造庞大表单。绘图数据与文字引用指向具体文件/字段/计算，截图和先前生成的图注不是数值依据。

图与图注来自同一结果不等于结果正确：先核实上游来源和方法，再核对展示。变换、排序、聚合后保存最终用于展示的数据与身份映射；不以可读标签作为可能重名的唯一键。

## 不随图形变化的检查

| 要保持的关系 | 需要核对的内容 |
|---|---|
| 身份与数量 | 图元对应什么实体/独立单位；选择前后数量、匹配和重复是否有依据；显示顺序能否回到源数据 |
| 数值与尺度 | 单位、变换、轴/色阶范围与方向、参考中心、分母、区间定义一致；没有静默截断、插补或聚合 |
| 设计与编码 | 颜色/形状/位置等含义明确，跨图稳定；配对、时间、空间及层级关系没有因排序或连接被误造 |
| 图与文字 | 每个数字和方向性陈述有来源；观察与推断分开，结论未超出分析所支持的证据层级 |
| 图与文件 | 同一最终对象和共同配置导出；图例、字体、标签、数据层和边界在最终尺寸下可读 |

遇到不同任务时按这些关系推导检查，而非增加专章。例如：组成需要分母及总量依据；趋势需要真实横坐标与连接依据；组间比较需要独立单位/重复关系及不确定性；关系或机制图需要边的方向、证据和“假设/实测”区分。任何图都不能仅因视觉分开、相关或连有箭头便写成显著或因果。

## 文字必须能够被核实或反驳

先写可验证观察，再按已有分析解释。“更近/更高/更强”等比较要声明比较对象、尺度及支持计算；没有对应计算时不写精确距离或强弱排序。数字取自记录，不从图像估读；缺少模型依据不追加显著性、主导效应、机制或外推。

逐项核对图注、正文和课件中的同一结论，发现矛盾先回到源数据，不假定图或文字哪一方正确。不同分析不一致时保留并说明差异来源，不能选有利结果；实验设计决定模型结构，展示模式不能替代设计事实。

## 执行与报告边界

可机械核查的身份、数值范围、颜色映射、导出尺寸等交给实际入口检查；当前程序只实现各自输入契约的有限检查，并未自动核验所有文字结论。未接入入口的代码必须另查，不能因文件存在或测试通过宣称全流程有效。

空输入、必要数值全缺失、图层丢失、身份错配和导出失败不交付成功结果。合法零值、常数、无符合条件发现则保留其真实含义，不改阈值或造数据。局部修复不重跑无关统计。

实际打开PNG及PDF/SVG渲染结果，检查文字/图例/区间边界、颜色可辨性及面板衔接；组图另验。有限检查不能发现所有遮挡或科学错误。复用运行记录区分technical、visual、semantic状态与未核实事项，不把pending改称通过。

新故障应归入上述关系，优先修复共享实现；具体复现输入放测试，不把错误截图、用户对话或逐图补丁写回主Skill。测试断言应检查输出事实和失败行为，不能用匹配文案证明智能体理解正确。
