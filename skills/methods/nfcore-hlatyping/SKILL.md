# 测序HLA高分辨分型（nf-core/hlatyping）

## 识别数据与研究目标

明确 WGS/WES/RNA 等输入、参考、样本和期望分型位数，核对本版本后端支持的数据类型。

## 方法选择

按适配的 HLA 分型路径组织数据，保留等位基因数据库版本和可能的多解。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `2.2.0`；`3237d20e7e611d8bbf8c37e637202dfe8a23e996` |
| 上游维护 | 未归档；使用这里固定的源码，不自动跟随新版本 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 引擎声明 | `!>=25.04.2`；还需核验 Java、容器和 profile |

## 根据数据确定参数

从数据类型、HLA 区域覆盖和后端支持选择分型方法及分辨率；多解和低覆盖保留置信限制，不能为了目标位数强制输出唯一高分辨型别。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |
| [输入模式-1.json](references/输入模式-1.json) | 准备 input 对应的样本表或输入文件时读取 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/hlatyping -r 3237d20e7e611d8bbf8c37e637202dfe8a23e996 -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

检查 HLA 区域覆盖、同源比对、等位不平衡和拷贝改变，避免把低覆盖模糊结果强制细分。

交付 HLA 候选及置信信息；高分辨率的格式不代表证据足够，临床配型需要专业复核与验证。
