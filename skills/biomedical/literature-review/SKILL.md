# 文献综述

一个文献问题包含两部分：找到领域专家会推荐的论文，以及把这些论文转化成比阅读清单更有用的内容——一份说明哪些结论已经确立、哪些仍有争议、哪些是新进展，以及哪些方面仍有空白的综合分析。这两部分都可能悄无声息地出错，而且在有人核查之前，看起来仍像是一份胜任的产出。

## 读懂请求真正要问什么

“X 对应的是哪篇论文”需要一两条具体引文；“关于 X 有哪些证据”需要综合分析；“比较 A 和 B”需要真正的比较，而不是两段并列摘要；“有哪些空白”需要指出空白，并以综述材料作为支持。面对只有两个词的非专业查询，应采用领域专家通常默认的范围，并在开头明确说明——例如：“我将其理解为询问人体随机对照试验证据；动物研究文献属于另一范围。”只有在答案确实会改变你的行动时，才提出澄清问题。

## 依据：先检索，再写作

对于广泛综述、研究空白和方法比较类请求，第一步是开展文献扫描——使用 `kernel.py` 中的 `search_openalex` / `crossref_lookup`、PubMed 查询、`web_search`，或当前接入的领域连接器（运行一次 `search_skills({prefix:"mcp-"})`，查看可用的文献/数据 MCP 服务器，例如 PubMed、Semantic Scholar、bioRxiv、ClinicalTrials.gov，并选择适合该领域的服务）——再根据返回结果组织答案。记忆负责确定分析框架，检索结果负责确定引文。真正的综述通常会包含约十五个或更多不同的原始研究 DOI，因为每项论断都应锚定到确立它的论文；只有少量综述引文的是阅读清单，而不是综合分析。当问题寻找的是某篇*特定*论文——“最初的”“奠基性的”、某个具名试验或方法——应找到后续研究共同引用的高被引原始论文，而不是介绍它的综述或新闻报道。

即使你对答案烂熟于心，这一要求也同样适用。为一篇你确信无误的论文——Transformer 论文、教科书常数或里程碑试验——解析 DOI，只需一次极快的工具调用，却决定了你提供的是经过核验的引文，还是关于引文的未经核验论断。核验应发生在工具轨迹中，而不是作为回复中的一句话。**你输出的 DOI 要么能解析到一篇真实且支持相应论断的论文，要么就是伪造；两者只需五秒即可查明。** 当你知道作者、年份和期刊却不知道 DOI 时，应通过 Crossref 或 OpenAlex 查找，而不是按模式补全；如果连这些信息也模糊不清，那就应该搜索，而不是直接引用。对于近期进展、有争议的发现，或任何你“记得”发生在知识截止时间附近或之后的事项，检索都不是可选步骤。

完成第一轮扫描后，选取最相关的两三项结果，沿引文图谱向两个方向各扩展一步：获取其参考文献列表（向后）和施引文献列表（向前），再把其中新增且相关的论文纳入集合，之后才开始写作。一个领域赖以建立的奠基性论文会在向后扩展中浮现；延伸或质疑首批结果的近期研究会在向前扩展中出现，而仅靠关键词扫描并不能可靠找到二者。`kernel.py` 中的 `expand_citations(doi)` 会从 OpenAlex 返回这两个方向的结果。

## 撤稿与空结果

轰动性论文容易被找到，正因为它们曾经轰动一时；其中一些后来被撤稿，或未能得到重复验证。Crossref 的 `update-to` 字段会标记撤稿；对任何高关注度或出人意料的发现，这项检查只需数秒。另一个相关陷阱，是某些问题的诚实答案其实是“并不存在这样的论文”：当有人询问“证明 X 的论文”，而 X 已被推翻或从未得到确立时，正确做法是说清这项主张、说明后来发生了什么，并指向真实证据所支持的结论，而不是提供最接近的引文。

## 综合不是摘要，而是比较

逐篇列出论文并各配一句摘要，只是一份书目。真正有用的是上层综合：这项发现得到了重复验证，那项没有；这三项研究都认同效应存在，却对机制意见不一；这种方法在场景 A 中占优，另一种在场景 B 中更好；2015 年的结果已被 2022 年的研究取代。应按主题或问题组织内容，而不是按论文排列。对于方法比较类请求，交付物应是权衡与建议，而不是两份摘要。

## 让文字承担综合工作

一个综述段落之所以值得存在，是因为它先提出*你的*综合判断，再用引文加以支持，而不是先抛出一条引文，再复述其发现。“Chen 2019 报告降低了 40%；Park 2020 报告降低了 35%”只是两张索引卡片。“这一效应确实存在但幅度有限，汇总估计集中在 35%–40%（Chen 2019；Park 2020）”才是综述。诊断方法是：依次只读每段的第一句话；如果它们共同构成你的论证，你写的是综合分析；如果它们只组成一串作者姓名，你写的只是披着段落外衣的注释书目。

## 写成论述，而非项目符号书目

产物应像一段达到同行评审标准的综述：由相互衔接的论证段落构成，每段提出一个论点，以行内引文作为依据，并自然过渡到下一段。一页内容若有 80% 都是项目符号，就是伪装成综述的阅读清单——它只告诉读者论文*存在*，没有说明这些论文合在一起证明了什么。仅在列表确实是合适结构时使用项目符号，例如参考文献附录、逐项对照表或具名方法的枚举；综合分析本身应使用连贯文字。如果你发现连续几行都以 `- 作者 年份发现……` 开头，那其实是一段尚未写成的正文。

## 根据证据校准表述

说明哪些发现具有里程碑意义、哪些属于近期进展；明确标记预印本；指出旧结果何时被修正或推翻。让置信程度与证据强度匹配：单一队列的发现应表述为“某个团队报告了 X”，Ⅲ 期随机对照试验的结果可以直陈，有争议的领域则要呈现双方证据，并坦率说明“尚无定论”。当问题本身包含有争议的前提时，应正面处理这个前提，而不是直接以其为基础展开。当请求关注研究空白时，应指出具体空白，并说明哪些证据证明它确实是空白——“需要更多研究”通常意味着你还没有找到真正的缺口。

## 把答案放进答案，并以实质内容开篇

综述的正文、引文和结论应直接出现在回复文本中，让读者立即看到。凡是不止查找一篇论文的任务，还应使用 `save_artifacts` 将完整综述保存为 Markdown 产物，以便读者获得一份整洁、可链接的文档；聊天回复本身仍然必须是答案，产物链接放在结尾，绝不能以“报告已保存：”开篇。只回复“我已保存一份包含 14 篇论文且 DOI 均经核验的综述”并不构成答案——先在聊天中写出实质内容，再链接产物。

第一句话应直接呈现读者想要的内容：发现、论文或比较结论。“下面是综合分析”“所有 DOI 均已通过 Crossref 核验；未发现撤稿标记”“我已核验每条引文”“报告截至今天仍为最新”都属于过程叙述，不应出现在聊天回复或保存的产物中。核验发生在工具轨迹里；读者会从能够解析的引文和经得住检查的论断中看出这一点。不要在输出任何位置写“DOI 已核验/无撤稿”——无论开头、结尾，还是产物标题下方的斜体副标题。产物正文与聊天回复遵循完全相同的规则：以实质内容开篇，也以实质内容收尾。目标文体应像精炼的方法学段落或达到同行评审标准的微型综述：先给出关键结果，再以行内 DOI 链接陈列支持证据，处理显而易见的反方观点或局限，最后说明仍未解决的问题。即使读者只看到第一段，也应已经得到答案。

行内引文应使用 Markdown 链接——`[作者 年份](https://doi.org/10.xxxx/xxxxxx)`——这样渲染后的正文显示为“（作者 年份）”，DOI 位于可点击的 `href` 中，正则表达式也仍能提取。如果 DOI 本身含有圆括号（某些出版商使用 PII 风格的后缀，例如 `Sxxxx-xxxx(NN)nnnnn-n`），应在 `href` 中将其 URL 编码为 `%28` 和 `%29`，以免 Markdown 链接在较简单的渲染器中断裂。不要使用编号式 `[1][2][3]` 参考文献，因为段落一旦重排，编号就会错位；原始 `(DOI: 10.xxxx/...)` 形式只用于纯文本输出——可见文本有一半都是标识符的句子，不符合同行评审级别的文风。链接文字中的作者姓名必须来自检索所得记录，绝不能凭记忆填写；在任何写作草稿或工作笔记中，都要让作者姓名与年份、DOI 始终同行（查找辅助函数正是为此返回这些信息；只有降级回退路径可能不带作者信息）。如果笔记只保留 DOI 而没有姓名，写正文时就只能凭记忆填入“作者 年份”，而记忆给出的往往只是听起来合理的姓名，并不一定属于那篇论文。`kernel.py` 提供 `verify_dois`、`crossref_lookup`、`search_openalex`、`expand_citations` 和 `style_pass`。章节标题应使用简短的名词短语（不超过六个词）；当有五个或更多主题时，将它们归入两三个父级 `##` 标题，并把其余标题降为 `###`。目标是让领域专家读到综述时会认同你的论述，看到他们自己也会点名的论文，而且找不到任何一项无法得到支持的论断。

## 保存前进行一次风格检查

保存产物前，对完整 Markdown 运行一次 `style_pass(draft)`。根据列出的问题完成一轮统一修改，然后保存；不要再次调用，也不要循环运行直到它返回 `ok`。它是静态检查，不是准入门槛；初稿第一次检查就无问题也很正常。该函数随本技能的 `kernel.py` 提供并会自动加载；如果 `style_pass` 不在 `dir()` 中，请读取本技能目录下的 `kernel.py` 并执行。
