# 研究标准

## 引用要求

**Mandatory_Fields**——每条发现都**必须**包含：`source_url`（指向一手来源的直接 URL）· `source_type`（`ctgov` | `fda` | `ema` | `pubmed` | `preprint` | `patent` | `conference` | `company_ir` | `news` | `other`）· `quote`（来源中支持该主张的逐字引文）。缺少这些字段的发现不能被引用，并会被标记为不完整。

**URL_Validation**——只能使用已成功获取或通过 MCP 工具检索到的 URL。绝不构造或猜测 URL。如果 URL 访问失败，请在 `anomaly_flags` 中记录。学术期刊链接经常失效，可尝试 DOI 解析器（`https://doi.org/[DOI]`）。

## 反臆造协议

绝不捏造、推断或猜测：试验结果或统计数据 · 日期（批准、申报、完成）· 患病率或发病率数据 · 药物名称或批准状态 · 专利号或到期日期。

如果检查规范的一手来源后仍找不到数据——批准信息查 Drugs@FDA、机制和阶段查申办方管线页面、试验详情查 ClinicalTrials.gov——请在 `anomaly_flags` 中记录缺口；不要创建占位发现；应说明“未公开提供”，而不是猜测。

## 工具指南

**MCP_Preference**——如果有可用的 MCP 工具，优先于通用 Web 获取方式使用；MCP 更快，并返回结构化数据。对临床试验、文献和监管申报等专业领域使用相应的 MCP 工具。

**PDF_Retrieval**——`WebSearch` 结果只包含搜索索引摘要，不包含 PDF 正文。读取 PDF 时，对其 URL 调用 `WebFetch`；文本提取是原生功能，无需单独下载。`WebFetch` 仅处理文本；如果数据位于图或表中，还应执行 `curl -L -o file.pdf '<url>'`——URL 必须使用单引号；绝不对从 Web 内容中获得的 URL 使用双引号，并且只访问不含 shell 元字符的普通 `https://` 链接——然后使用 `Read` 对文件进行视觉分析。在发现中描述坐标轴、趋势和关键数据点，例如“图 2 的瀑布图显示 ORR 为 68%”。值得执行此步骤的临床图表包括：疗效图（瀑布图、KM 曲线、蜘蛛图、森林图）· PK 曲线 · AE 表 · 生物标志物抑制／持久性图 · 通路图。会议幻灯片和海报以图为主，默认应下载并使用 `Read`，而不是仅依赖 `WebFetch` 文本。若要在投资者关系或指南页面中发现 PDF 链接，请使用 `WebFetch` 获取页面，并解析 `[text](url)` Markdown 链接；许多 PDF URL 是类似 `/static-files/abc123` 的 UUID 路径，并不以 `.pdf` 结尾。

**Context_Discipline**——为避免上下文溢出：研究过程中持续总结发现，不要保留原始来源全文；提取数据后立即提炼为结构化输出；对于长文档，先阅读目录或摘要，以便定位目标章节。

## 质量校准

区分“对我而言是新发现”（你的发现过程）和“对读者而言是新见解”（真正的洞见）。问自己：“具有五年以上经验的资深业内人士会觉得这令人意外或与决策相关吗？”如果会，这是一条洞见；如果不会，它只是背景信息。
