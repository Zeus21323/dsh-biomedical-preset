# 损坏FASTQ恢复与读段配对修复（nf-core/fastqrepair）

## 识别数据与研究目标

从交付文件与报告中识别有问题的 FASTQ.gz 副本、单双端关系和错误表现；先保留原件及摘要，明确允许丢弃哪些不完整记录。

## 方法选择

区分压缩损坏、四行格式错误、序列质量长度不一致与 mate 顺序错乱，再使用本版本支持的修复路径。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `1.1.1`；`70a38209407b9367a9ff7ab8b26d84cb1983ea18` |
| 上游维护 | 未归档；使用这里固定的源码，不自动跟随新版本 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 引擎声明 | `!>=25.10.4`；还需核验 Java、容器和 profile |

## 根据数据确定参数

根据压缩、记录长度和 mate 检查定位故障，再选择相应修复；统计实际丢弃记录，不以通用丢弃比例替代完整性判断。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/fastqrepair -r 70a38209407b9367a9ff7ab8b26d84cb1983ea18 -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

统计恢复、丢弃、未配对及重新排序的记录，抽查 read name 和长度；修复后再次验证压缩与 FASTQ 结构。

输出修复副本和损失审计；恢复出的可读文件不意味着没有选择性丢失，后续分析需考虑损坏造成的偏倚。
