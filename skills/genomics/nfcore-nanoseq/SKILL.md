# Nanopore拆样质控与比对（nf-core/nanoseq）

## 识别数据与研究目标

核对 Nanopore 输入格式、basecalling 状态、建库条形码、参考与目标分子类型；不同版本的原始信号支持需单独确认。

## 方法选择

选择本版本提供的拆样、质控和比对组合，保留测序模型与读段类别，避免将已有 FASTQ 当作原始信号重新解释。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `3.1.0`；`6e563e54362cddb8e48d15c156251708c22d0e8d` |
| 上游维护 | 未归档；使用这里固定的源码，不自动跟随新版本 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 引擎声明 | `!>=22.10.1`；还需核验 Java、容器和 profile |

## 根据数据确定参数

从实际信号格式、basecalling 模型、条形码与读长质量分布确定处理起点和过滤；RNA 与 DNA 使用适配路线，FASTQ 不足以恢复原始信号。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |
| [输入模式-1.json](references/输入模式-1.json) | 准备 input、protocol 对应的样本表或输入文件时读取 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/nanoseq -r 6e563e54362cddb8e48d15c156251708c22d0e8d -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

汇总长度、质量、产量、barcode 分配和比对覆盖，区分低质量 reads 与参考不匹配。

交付拆分与比对数据、测序 QC 和版本说明；这些预处理产物不自动包含变异检测或表达统计结论。
