# 面向非技术用户的遗传研究操作导航

这是智能体的工作规范，不是要求用户学习的软件手册。用户只需用自己的话说明疾病/基因和研究愿望，并提供已有资料。不要声称覆盖所有口语或保证自动触发率；用意图、输入、阶段、异常和反例共同识别需求。

## 初次对话怎么做

1. 用户只有“研究某疾病、想毕业/发文章”：先确认想解释病因、找候选机制还是做风险预测，了解是否已有数据；问题一次只问少量。不得推定必须做MR、GWAS或一套公共数据拼接分析。
2. 用户交文件：经授权读取表头、文件类型和少量内容，结合原始研究元数据识别个体基因型、汇总统计、表达矩阵或已有结果；不要把字段辨认任务交给新手。表达差异表不能直接作为MR暴露工具，只有P值不能伪造beta和SE。
3. 用户已给研究设计：检查对比、样本、祖源、坐标和独立性，指出会改变结论的缺口；能从资料核实的信息不重复询问。
4. 用户要求执行：说明将处理哪些输入、哪些软件、预计资源和输出位置。由智能体准备配置与脚本，用户确认研究事实、授权和成本，不要求其决定算法参数。
5. 有真实结果：立即作图、打开图片复核、解释结论，再提出有研究理由的下一步；不要止于一串让用户自行运行的命令。

咨询只授权咨询；数据下载、队列上传和大规模计算不因“想毕业”自动获得授权。

## 19个入口按需衔接

| 用户表达或实际输入 | 应进入的任务 | 先排除的误用 |
|---|---|---|
| 这个蛋白/因素会导致疾病吗；两者谁影响谁 | 孟德尔随机化因果分析 | 无工具、同源混杂、不同方向沿用同一工具集 |
| 有病例对照及基因型；想找遗传易感位点 | GWAS关联分析 | 表型反编码、亲缘/结构、低MAC与模型不适配 |
| 表格合不上；OR、坐标、字母方向不一致 | GWAS汇总统计质控与标准化 | 仅改列名就声称协调、显著子集当全量 |
| 样本数对不上；病例比例奇怪；批次问题 | 基因型与表型关联分析质控 | 静默丢样本、把元数据匹配视为全部QC |
| 多个研究结果能否合并；人群之间不同 | GWAS荟萃与跨祖源分析 | 重复队列、不同单位、不处理重叠 |
| 一片区域都显著，到底哪个位点重要 | GWAS精细定位 | clumping当精细定位、错序/错祖源LD |
| 两个性状/蛋白在同区域，是否同一信号 | 遗传共定位分析 | 多信号强用单信号、H4等同中介 |
| 基因或蛋白能否做药物靶点 | 分子QTL与药物靶点因果优先排序 | 结合伪影、相关cis工具当独立、遗传效应等同药效 |
| 测序里有很多罕见变异；想按基因看 | 稀有变异关联分析 | 未定义mask、频率/注释阈值随结果改变 |
| 遗传因素解释多少；两种病是否共享遗传背景 | 遗传力、遗传相关与Genomic SEM分析 | 遗传相关当因果、缺适配LD与足够精度 |
| GWAS能否关联到组织中的表达 | TWAS转录组关联分析 | 表达权重不匹配、TWAS显著当因果基因 |
| 这些位点关联什么功能/通路 | GWAS功能解释 | 最近基因等同功能基因、背景集错误 |
| 同一位点附近有多个基因，优先研究谁 | GWAS位点到基因优先排序 | 多来源实际共用数据却重复计分 |
| 能否给个人预测风险 | PRS多基因风险评分 | 训练测试泄漏、缺外部验证或基线风险 |
| 这个基因/评分还关联哪些疾病或安全性 | PheWAS全表型关联分析 | 忽略多重检验、直接宣称药物副作用 |
| 芯片缺很多位点；需要参考推断 | 基因型填充与相位推断 | build/面板错误、未授权上传个体数据 |
| 样本聚成几团；不同人群结果不同 | 群体结构与祖源分析 | PCA群团过度解释、将祖源等同种族本质 |
| 位点太靠近；工具不独立；参考矩阵报错 | 连锁不平衡与单倍型分析 | r²代替带符号r、等位基因/顺序错配 |
| 这个变异在不同人群常见吗 | 群体等位基因频率分析 | 分母、倍性、低覆盖或参考人群不适配 |

宽泛选题可由可用的“公共组学多数据集研究设计与证据报告”先承接；能力未安装时保留研究问题与所需输入，不假装已经调用。每个专业入口自身仍能解释起点与缺口，不依赖用户认识路由名称。

## 现成脚本与原生操作的边界

现成入口包括：汇总统计标准化、样本表审查、独立研究固定效应meta、证据矩阵整理、LD结构审查、PLINK2/REGENIE调用、GWAS作图、TwoSampleMR基础正式流程及作图、SuSiE-RSS精细定位、单信号coloc ABF与图。它们的适用输入由各自指南明确限制，不是任意文件通用分析器。

MVMR、MR-PRESSO、RAPS、CAUSE、SMR/HEIDI、coloc-SuSiE、SAIGE、稀有变异、LDSC/Genomic SEM、TWAS、PRS等扩展按各入口的官方原生操作指南执行；必要时在用户工作区生成项目脚本，先核验当前安装版函数/命令和参考资源。不虚构已经封装的一键参数，不因依赖缺失改用无依据的近似方法。一样本、非线性、家系内与中介MR是独立研究设计，缺必要输入时停在设计与准备清单。

## 生成项目脚本必须遵守

- 先冻结研究问题、主要分析、对比、阈值及敏感性计划；新增探索性分析要明确标记。
- 输入映射、build、祖源、效应尺度、病例定义、N和参考来源可追溯；不推测、不补造数值。
- 路径与shell分开传参，输入只读，输出使用仓库外新目录；保护已有输出，不自动安装、不暗中联网、不记录令牌。
- 环境/接口核查和dry-run先于昂贵计算；记录实际版本、配置、命令、输入校验值、退出状态、排除原因和种子。dry-run不等于科学分析通过。
- 区分completed、failed、not_applicable、not_run、inconclusive；后端退出0还需检查产物与模型状态。失败/未收敛文件不得被后续绘图误当成功结果。
- 不把测试数据、基因型、公开示例、LD面板、模型权重、缓存、运行日志或结果图加入Skill仓库。检查时临时数据及图留在仓库外，明确为验证用途。

## 可视化直接交付的具体步骤

1. 读取已保存真实结果与状态；定义横纵轴、单位、统计对象、CI/后验含义和多重校正。缺所需统计则说明无法作图，不造点、不造区间。
2. 根据主张选图：关联扫描用曼哈顿/QQ，效应用森林图，区域共享用成对区域图和先验敏感性图，精细定位用PIP/可信集，预测用校准/区分度，证据用保留冲突与缺失的矩阵。
3. 先输出完整作图数据，再输出PDF/SVG与高清PNG。文字与轴尽量可编辑，密集点可注明栅格化；字体须覆盖字符，色盲友好，颜色之外用形状/线型区分。
4. 自动打开或渲染每张图检查：成稿尺寸下字体可读、标签不裁切、图例不遮挡、区间/零线正确、图表数字一致、阴性未隐藏；不合格则调整后重画。600dpi本身不等于论文级。
5. 有界面时直接展示关键图并提供文件链接，附底层表和含实际N/模型/单位/数据来源的图注。无界面时交付图件及明确的打开路径，不能仅交作图代码并声称图已检查。

## 每份结果解读至少回答

这项分析回答什么问题；实际效应和不确定性是什么；依据哪张表/图；质量和识别假设哪些有证据、哪些仍未知；有哪些技术或生物学替代解释；阴性、冲突及未完成项是什么；下一步验证如何改变结论。关联、预测、共享遗传信号、在假设下的因果支持、实验因果和临床药效分层表述。不承诺发表、毕业、机制已证实或临床有效。
