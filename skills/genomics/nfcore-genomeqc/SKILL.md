# 多基因组与注释质量比较（nf-core/genomeqc）

## 识别数据与研究目标

核对交付包中的待比较组装、对应注释、物种关系和评价目的；确保统计指标的定义与基因组规模可比。

## 方法选择

按同一套评估设置比较完整性、连续性和注释表现，区分同一样本的候选组装与不同物种的生物差异。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `1.0.0`；`e1aa8943b4752b9e540b2370aa2454ca9ba04742` |
| 上游维护 | 未归档；使用这里固定的源码，不自动跟随新版本 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 引擎声明 | `!>=25.10.4`；还需核验 Java、容器和 profile |

## 根据数据确定参数

根据物种选择完整性参考谱系，用同一评价口径比较候选；结合污染、重复和基因完整性解释连续性，不能用跨物种统一 N50 门槛淘汰样本。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |
| [输入模式-1.json](references/输入模式-1.json) | 准备 input 对应的样本表或输入文件时读取 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/genomeqc -r e1aa8943b4752b9e540b2370aa2454ca9ba04742 -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

识别污染、冗余、缺失基因及注释版本偏差，避免只依据单一 N50 或 BUSCO 数值排序。

输出多组装比较表、质量图和取舍说明；质量评估支持候选选择，不证明所有区域或注释都正确。
