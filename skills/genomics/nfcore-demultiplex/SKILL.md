# 测序样本拆分与条形码处理（nf-core/demultiplex）

## 识别数据与研究目标

从交付文件与报告中识别原始测序文件、样本索引表、平台和试剂版本，核对 i7/i5 方向、单双索引及 lane 关系。

## 方法选择

根据实际输入和本版本后端选择拆分方法，明确条形码错配容忍度和 read structure；不要对已拆分 FASTQ 再假定存在原始索引读段。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `1.7.1`；`fbec8e442f0599f8b74876e62263af05b9a41d33` |
| 上游维护 | 未归档；使用这里固定的源码，不自动跟随新版本 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 引擎声明 | `!>=25.10.2`；还需核验 Java、容器和 profile |

## 根据数据确定参数

从试剂说明、索引表和读段结构确定索引方向与错配容忍；用未分配比例及索引冲突复核，不能为提高分配率随意增加容错。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |
| [输入模式-1.json](references/输入模式-1.json) | 准备 input 对应的样本表或输入文件时读取 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/demultiplex -r fbec8e442f0599f8b74876e62263af05b9a41d33 -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

汇总 assigned、undetermined 与 index mismatch 比例，检查索引碰撞、index hopping 和样本产量异常。

交付按样本划分的数据与拆分统计；样本命名正确不等于生物身份已验证，异常低产量需回查索引设计。
