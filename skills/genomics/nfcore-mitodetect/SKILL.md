# 线粒体分析流程可用性审查（nf-core/mitodetect）

## 识别数据与研究目标

先区分用户需要线粒体变异/异质性结果还是原始读段 QC；本次固定开发源码仅调用 FastQC 和 MultiQC，没有线粒体调用模块。

## 方法选择

核对所请求 endpoint 与实际实现的差距；只有一般 FASTQ 质控可按现有入口准备，线粒体变异需求应转交合适的检测任务。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `dev`；`1fb96f0dc7a4f569414ee4256b78a03cc8c3f98e` |
| 上游维护 | 开发版本；按当前代码实际实现的范围使用 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 已核查的实现边界 | 已检查 workflow：只有 FastQC 和 MultiQC；当前 revision 不提供线粒体变异或异质性结果。 |
| 引擎声明 | `!>=24.04.2`；还需核验 Java、容器和 profile |

## 根据数据确定参数

先核实读段质量与线粒体目标的可支持性；本版本没有异质性调用模块，不能设置一个等位频率阈值就声称能检测线粒体低频变异。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |
| [输入模式-1.json](references/输入模式-1.json) | 准备 input 对应的样本表或输入文件时读取 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/mitodetect -r 1fb96f0dc7a4f569414ee4256b78a03cc8c3f98e -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

审查只能引用真实产生的读段质量证据，不能从通用 MultiQC 推导线粒体覆盖、NUMT 排除或异质性比例。

输出可用性判断、缺失能力和已存在的 QC 说明；不生成或宣称线粒体 VCF、异质性或疾病解释结果。
