# 测序数据专用质量检查（nf-core/seqinspector）

## 识别数据与研究目标

从交付文件与报告中识别数据清单、平台、文库类型与用于分组报告的元数据，明确检查原始 reads 还是比对结果。

## 方法选择

按输入阶段选择该版本适用的 QC 组合，保持批次和组别可追踪，避免把技术重复当作独立生物学样本。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `1.1.2`；`6aa08aabb00cdbb0f5b62adf2749b472e794ba04` |
| 上游维护 | 未归档；使用这里固定的源码，不自动跟随新版本 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 引擎声明 | `!>=25.10.4`；还需核验 Java、容器和 profile |

## 根据数据确定参数

按数据阶段、平台和批次挑选有意义的 QC 指标；结合批内分布与实验背景定位异常，不把自动告警直接当作删除样本的依据。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |
| [输入模式-1.json](references/输入模式-1.json) | 准备 input 对应的样本表或输入文件时读取 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/seqinspector -r 6aa08aabb00cdbb0f5b62adf2749b472e794ba04 -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

比较样本与组别质量分布，识别低产量、污染、重复、链特异性或覆盖异常；阈值按 assay 和目的解释。

交付样本级与分组 QC 汇总及异常清单；QC-only 流程不提供差异表达、变异检测或因果结论。
