# RNA与DNA联合体细胞变异分析（nf-core/rnadnavar）

## 识别数据与研究目标

从交付文件与报告中识别同一患者的 DNA/RNA、肿瘤与正常关系、参考和表达信息，明确哪些数据层实际存在。

## 方法选择

依据本版本流程联合候选与表达证据，区分 DNA 发现、RNA 支持、RNA 特异编辑及覆盖缺失。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `1.0.0`；`8e8debdb0e7208218a4a2f852de7c741a69ca448` |
| 上游维护 | 未归档；使用这里固定的源码，不自动跟随新版本 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 引擎声明 | `!>=25.10.4`；还需核验 Java、容器和 profile |

## 根据数据确定参数

以 DNA 调用质量和 RNA 位点覆盖分别设定支持条件，RNA 编辑与剪接伪影独立检查；RNA 未表达不能被解释为 DNA 候选已排除。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |
| [输入模式-1.json](references/输入模式-1.json) | 准备 input、input_restart 对应的样本表或输入文件时读取 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/rnadnavar -r 8e8debdb0e7208218a4a2f852de7c741a69ca448 -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

检查跨模态样本身份、剪接比对、等位表达、污染和低覆盖，避免以 RNA 无支持直接否定 DNA 事件。

交付带分层证据的体细胞候选；RNA 支持可补充转录证据，不自动决定致病性或可靶向性。
