# 历史肝脏CT流程实现审查（nf-core/liverctanalysis）

## 识别数据与研究目标

明确用户期望的 CT 输入与肝脏分析结果；该归档 revision 的 workflow 仍是 INPUT_CHECK、FastQC、MultiQC 模板，不能接收为已实现的 CT 分析。

## 方法选择

对照固定源码形成接口与任务不匹配报告，指出没有可核查的肝脏影像处理链路；不要将 CT 文件交给模板中的测序 QC。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |

| 已核查的实现边界 | 已检查 workflow：仍为测序 QC 模板，没有可用的肝脏 CT 处理链路；不得用此入口处理 CT。 |
| 引擎声明 | `!>=21.04.0`；还需核验 Java、容器和 profile |

## 根据数据确定参数

读取 CT 头信息与实际影像需求后排除此模板作为执行路线，交接可用影像方法；没有 CT 处理实现时不生成分割参数或虚构影像阈值。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |

## 质控与解释

检查主入口、workflow 和参数模式的证据一致性；模板示例、流程名称和 README 目标都不能证明分割或影像定量已经存在。

交付版本审查及适用的影像任务交接建议。本 Skill 不启动此源码处理 CT，不生成肝脏分割、测量或临床结论。
