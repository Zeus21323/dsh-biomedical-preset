# 历史多模式定量质谱流程（nf-core/quantms）

## 识别数据与研究目标

明确 DDA-LFQ、同位素标签或 DIA 等实验模式、原始质谱、序列库和设计表，固定归档版本。

## 方法选择

按该 revision 的模式兼容性组织鉴定、FDR 与定量，不混用标签通道与无标签样本设计，也不因归档而静默替换流程。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `1.2.0`；`fa34d79f5071ae064d1438ad59c53b0093622ae5` |
| 上游维护 | 已归档；用于明确的历史分析或复现审查 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 引擎声明 | `!>=23.04.0`；还需核验 Java、容器和 profile |

## 根据数据确定参数

由采集方式和通道设计决定兼容路径，依据干扰、鉴定错误与缺失选择定量过滤；标签通道与生物样本分别映射，不能把技术通道当独立重复。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/quantms -r fa34d79f5071ae064d1438ad59c53b0093622ae5 -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

检查不同层级鉴定错误率、通道串扰/批次、缺失及蛋白推断，记录定量单位与归一化。

交付所选历史模式的定量/QC 和复现范围；归档流程结果仍需实验设计支持，迁移到新工具应明确重新验证。
