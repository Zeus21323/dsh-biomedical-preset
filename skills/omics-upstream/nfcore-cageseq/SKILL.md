# CAGE转录起始位点与标签计数（nf-core/cageseq）

## 识别数据与研究目标

从交付文件与报告中识别 CAGE reads、文库结构、参考和样本分组，确认标签与链方向规则。

## 方法选择

按流程进行修剪、比对、CAGE tag 整理和可用的起始位点分析，保持 CTSS 或标签聚合定义一致。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `1.0.2`；`838d2a5165edb86439d7ff0400bd385d6bcf6927` |
| 上游维护 | 未归档；使用这里固定的源码，不自动跟随新版本 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 引擎声明 | `>=20.04.0`；还需核验 Java、容器和 profile |
| 语法兼容 | 原生入口含历史 process/channel 写法；先核验匹配的 Nextflow 版本 |

## 根据数据确定参数

根据文库方向、标签质量与 CTSS 分布选择修剪和聚合尺度；按重复支持判断起始簇，不能把低深度样本的缺失标签直接当作起始点消失。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/cageseq -r 838d2a5165edb86439d7ff0400bd385d6bcf6927 -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

检查 rRNA/污染、标签长度、起始位点聚集及重复一致性，评估低计数聚类的不稳定性。

输出 CAGE 标签计数与起始相关结果；启动子活性不等同完整转录本丰度或蛋白表达。
