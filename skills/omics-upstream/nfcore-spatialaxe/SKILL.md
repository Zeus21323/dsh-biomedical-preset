# Xenium与Artera空间数据质控（nf-core/spatialaxe）

## 识别数据与研究目标

从交付文件与报告中识别 Xenium 或 Artera 数据、平台版本、样本与组织信息，辨明上游计数、分割和坐标文件。

## 方法选择

依据本版本的平台适配完成数据读取、处理和 QC，保留原始细胞 ID 与探针/特征标识。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `1.0.1`；`748d310ac01943c97a15bdbc27ec2525a3ee0a96` |
| 上游维护 | 未归档；使用这里固定的源码，不自动跟随新版本 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 引擎声明 | `!>=25.04.0`；还需核验 Java、容器和 profile |

## 根据数据确定参数

根据平台背景探针、细胞面积和局部密度选择 QC 条件；异常区域先结合组织图像定位，不能因局部低计数自动剔除整类细胞。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |
| [输入模式-1.json](references/输入模式-1.json) | 准备 input 对应的样本表或输入文件时读取 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/spatialaxe -r 748d310ac01943c97a15bdbc27ec2525a3ee0a96 -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

检查每细胞分子数、背景、分割异常和组织区域覆盖，分别记录平台特有的失败信号。

交付处理对象与空间 QC；跨平台差异可能受 panel、检测与分割策略影响，不能直接当作生物变化。
