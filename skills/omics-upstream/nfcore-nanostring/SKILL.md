# NanoString nCounter表达分析（nf-core/nanostring）

## 识别数据与研究目标

从交付文件与报告中识别 nCounter 原始计数/本版本所需文件、panel、阳性阴性对照、管家基因和样本设计。

## 方法选择

依据探针与实验控制选择背景处理和归一化，明确内参选择及批次校正，避免套用 RNA-seq 的库大小假设。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `1.3.3`；`6f0b2d537a1f06e8fe1d6c63d7c409009141aa62` |
| 上游维护 | 未归档；使用这里固定的源码，不自动跟随新版本 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 引擎声明 | `!>=25.10.2`；还需核验 Java、容器和 profile |

## 根据数据确定参数

从阴阳性对照、背景分布与候选内参稳定性选择背景校正和归一化；内参在目标条件不稳定时调整依据，不能直接沿用公司默认内参列表。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |
| [输入模式-1.json](references/输入模式-1.json) | 准备 input 对应的样本表或输入文件时读取 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/nanostring -r 6f0b2d537a1f06e8fe1d6c63d7c409009141aa62 -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

检查成像、结合密度、阳性对照线性、检测限与内参稳定性，标记低质量样本和低于背景的特征。

交付归一化表达、QC 和支持的比较结果；panel 限制了可测基因范围，未检测不能代表全转录组阴性。
