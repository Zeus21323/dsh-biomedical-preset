# 稳定表达基因与qPCR内参筛选（nf-core/stableexpression）

## 识别数据与研究目标

从交付文件与报告中识别一个或多个表达数据集、样本条件和物种，明确希望稳定的适用范围而非只看总体均值。

## 方法选择

按此版本支持的稳定性评价方法比较候选，处理低表达、缺失和跨平台尺度，保留每个数据集的结果。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `dev`；`10736a5a75afac14a6301163a3ef91510ff07eff` |
| 上游维护 | 开发版本；按当前代码实际实现的范围使用 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 引擎声明 | `!>=26.04.4`；还需核验 Java、容器和 profile |

## 根据数据确定参数

依实际条件范围、低表达噪声和跨平台尺度选择稳定性评价；检查候选在每个条件中的变化，不能因总体方差小就忽略某一关键组的系统偏移。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |
| [输入模式-1.json](references/输入模式-1.json) | 准备 datasets 对应的样本表或输入文件时读取 |
| [输入模式-2.json](references/输入模式-2.json) | 准备 gene_id_mapping 对应的样本表或输入文件时读取 |
| [输入模式-3.json](references/输入模式-3.json) | 准备 gene_length 对应的样本表或输入文件时读取 |
| [输入模式-4.json](references/输入模式-4.json) | 准备 gene_metadata 对应的样本表或输入文件时读取 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/stableexpression -r 10736a5a75afac14a6301163a3ef91510ff07eff -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

检查候选是否受处理、细胞组成或批次影响，用独立数据或实验验证而非仅按最小变异排序。

交付稳定基因候选及条件范围；计算筛选的内参仍需在目标 RT-qPCR 实验验证，不能声明普遍稳定。
