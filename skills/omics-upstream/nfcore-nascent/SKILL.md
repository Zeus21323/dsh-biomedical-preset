# 新生转录数据处理（nf-core/nascent）

## 识别数据与研究目标

明确 PRO/GRO/NET 等具体新生转录实验、reads 方向、spike-in、参考和重复，核对该版本支持的协议。

## 方法选择

按协议设置修剪、链特异比对与信号生成，保留聚合酶相关信号与成熟 RNA 的区别。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `2.3.0`；`7d4fe61975015f652c271886e661764b05cfd3bf` |
| 上游维护 | 未归档；使用这里固定的源码，不自动跟随新版本 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 引擎声明 | `!>=24.04.2`；还需核验 Java、容器和 profile |

## 根据数据确定参数

根据协议方向和片段特征确定修剪与计数位置，按真实 spike-in 设计评估归一化；没有兼容实验信息时不把普通 RNA-seq 当作新生转录数据。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |
| [输入模式-1.json](references/输入模式-1.json) | 准备 input 对应的样本表或输入文件时读取 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/nascent -r 7d4fe61975015f652c271886e661764b05cfd3bf -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

评估 rRNA、基因体/启动子信号、链偏倚和 spike-in 稳定性，处理低覆盖和批次差异。

交付新生转录轨道及实际分析结果；信号代表转录活动相关读出，不能直接替代稳态 mRNA 表达。
