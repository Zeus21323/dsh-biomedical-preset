# 单细胞计数矩阵下游处理（nf-core/scdownstream）

## 识别数据与研究目标

从交付文件与报告中识别已定量的 H5AD、SingleCellExperiment/Seurat 或本版本接受的计数文件与样本表，标明 raw counts、过滤矩阵和元数据。

## 方法选择

根据数据现状选择格式转换、环境 RNA、doublet、QC、整合、降维及聚类，保留未整合表达和原始计数。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `dev`；`9b46a2b66047781886d7b2f33dba63f586054872` |
| 上游维护 | 开发版本；按当前代码实际实现的范围使用 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 引擎声明 | `!>=25.10.4`；还需核验 Java、容器和 profile |

## 根据数据确定参数

按样本、组织、细胞或细胞核来源观察基因数、UMI、线粒体比例和双细胞证据后确定 QC；整合强度与聚类分辨率用生物信号保留和稳定性复核，不把全队列统一阈值当作默认科学结论。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |
| [输入模式-1.json](references/输入模式-1.json) | 准备 analysis_plan 对应的样本表或输入文件时读取 |
| [输入模式-2.json](references/输入模式-2.json) | 准备 input 对应的样本表或输入文件时读取 |
| [输入模式-3.json](references/输入模式-3.json) | 准备 celldex_reference 对应的样本表或输入文件时读取 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/scdownstream -r 9b46a2b66047781886d7b2f33dba63f586054872 -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

检查每样本细胞质量、批次混合和生物信号保留，不以 UMAP 混合好作为整合成功的唯一依据。

交付分析对象与 QC，确认实际实现的模块；细胞数量不能替代供者重复，差异推断需匹配实验设计。
