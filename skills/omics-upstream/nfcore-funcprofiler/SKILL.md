# 微生物读段功能组成分析（nf-core/funcprofiler）

## 识别数据与研究目标

从交付文件与报告中识别宏基因组/宏转录组 reads、样本信息及功能数据库，明确目标是功能潜力还是表达活动。

## 方法选择

按本版本的 read-based 功能路径进行匹配、定量和功能汇总，保留数据库层级及归一化单位。

先核对 [版本约定](references/流程约定.json)。

| 核对项 | 固定范围 |
|---|---|
| 上游版本 | `dev`；`a8101edc6deec2bf5eed2e27682f94512857844e` |
| 上游维护 | 开发版本；按当前代码实际实现的范围使用 |
| 本地运行 | 未进行真实分析运行；不能据本 Skill 文件声称实跑通过 |
| 引擎声明 | `!>=25.10.4`；还需核验 Java、容器和 profile |

## 根据数据确定参数

根据 DNA/RNA 类型、读段质量和数据库覆盖选择匹配及汇总层级；归一化单位与比较目标一致，DNA 功能潜力不能解释成实际转录活动。

| 决策与配置 | 处理要求 |
|---|---|
| 事实与缺口 | 先读现有文件和报告；不能据文件名猜实验类型、参考或样本关系；只补问无法核实且会改变分析的背景 |
| 参数来源 | 区分协议必需设置、数据估计、方法默认和研究选择；说明实际取值及理由，不要求用户填写专业参数 |
| 可执行配置 | 仅把已支持的选择映射为当前版本的原生字段；不支持的步骤另行交接，不虚构开关 |
| 阈值复核 | 默认值先评估适用性；依据质控、对照及敏感性检查调整，不能按显著结果数量调参 |

| 资料 | 使用时机 |
|---|---|
| [参数模式.json](references/参数模式.json) | 编写 params.json 时核对字段、类型、枚举及条件约束 |
| [输入模式-1.json](references/输入模式-1.json) | 准备 databases 对应的样本表或输入文件时读取 |
| [输入模式-2.json](references/输入模式-2.json) | 准备 input 对应的样本表或输入文件时读取 |

仅在已授权且配置齐备时运行。

```bash
nextflow run nf-core/funcprofiler -r a8101edc6deec2bf5eed2e27682f94512857844e -params-file params.json
```

模式文件的许可见 [LICENSE](LICENSE)。

## 质控与解释

检查功能映射率、未注释比例、多重匹配、基因长度和物种组成影响。

交付基因/功能家族或通路丰度及 QC；DNA 功能潜力不能直接解释为通路活性，RNA 丰度也非代谢通量。
